## Authentication and rollout

Access JWTs now carry the saved session ID and are refused when that session is revoked, expired, missing or belongs to another user. Current database role/status remain authoritative. The existing refresh rotation grace window is retained, while explicit global sign-out and password-related termination expire reusable rotation history. Replay-driven revocations commit before the API returns 401.

Deploy all backend instances together. Existing access cookies without a session ID will receive 401 and can be replaced through the frontend's existing refresh flow if the refresh cookie remains valid. Clients using old bearer tokens must obtain a new session. No data migration is required for this change.

Full browser login/logout, password change, refresh across multiple real tabs/devices, CSRF/CORS behavior with authenticated cookies, production throttling, and administrator account changes still require staging verification. No authenticated live session was used.

## Startup follow-up — PostgreSQL URL validation

The subsequent startup logs reported Prisma P1012 with the PostgreSQL protocol requirement. A redacted inspection confirmed that the saved `.env` contains a `mysql://` connection URL. PostgreSQL remains the intended database. No local PostgreSQL service or listener was found, and no replacement PostgreSQL credentials were available. The saved file still used MySQL when rechecked after the user's confirmation; it was not rewritten with invented or placeholder credentials.

Two startup defects were corrected:

- `src/config/env.validation.ts` now rejects incompatible database URL protocols immediately, with an actionable error that omits the connection URL and credentials.
- `src/prisma/prisma.service.ts` now retries only temporary connection failures (`P1001`, `P1002`, `P1017`). Invalid schema/URL and authentication/access failures stop after the first attempt. The existing retry limit and backoff remain in effect for temporary failures. The code distinction follows the [Prisma error reference](https://docs.prisma.io/docs/orm/reference/error-reference).

`.env.example` documents that the connection must target a real PostgreSQL service; changing only a MySQL URL's prefix does not convert the database. `src/config/env.validation.spec.ts` was extended and `src/prisma/prisma.service.spec.ts` was added.

Follow-up verification: **19 unit suites / 106 tests passed**, including 18 focused configuration/retry cases. TypeScript, focused ESLint, Nest production compilation and whitespace checks passed. No migrations, database mutations or changes to `.env` were performed. The earlier 157 HTTP access tests were not rerun for these startup-only changes.

Connectivity remains **BLOCKED** until `DATABASE_URL` contains the actual PostgreSQL connection URL, saved directly in `.env`. After saving it, restart the backend and verify a read-only connection before running database-backed workflows. Total changed/added files after this follow-up: **24**.
